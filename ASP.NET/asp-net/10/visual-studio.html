Visual Studio

Although an IDE is not required, it does provide many useful features to improve developer productivity. There are several IDE choices available, but we will be using the full version of Visual Studio on Windows.

Solution File

When using ASP.NET Core, it is very common to end up with multiple separate .NET projects. As an example, you may have:

  • API project that hosts a collection of HTTP endpoints

  • Razor Pages project for a browseable website

  • Class library project containing reusable business logic

  • Unit test project

It is useful to be able to be able to work with multiple projects in Visual Studio at the same time. This makes it easier to manage references between the projects and debug code across them. To accomplish this, a .NET solution file (.sln) can be used.

Create a solution and add a project

  1. Make sure you are in the AddressBook directory (not AddressBook.API) and use the CLI to create an .sln file.

    dotnet new sln -n AddressBook

  2. Use the CLI to add the AddressBook.API project to the solution.

    dotnet sln add ./AddressBook.API/AddressBook.API.csproj

  3. Open Visual Studio.

  4. Choose to open a Project/Solution and select the AddressBook.sln file.

    You should see the AddressBook solution and the AddressBook.API project in Visual Studio’s Solution Explorer window. You should also notice that Visual Studio created a new folder named Properties and added a file named launchsettings.json

Launch Settings

Many developer tools (Visual Studio, VS Code, Rider) will look for a launchsettings.json file. This file contains one or more launch "profiles". Each launch profile has a name and some settings that control how the app is launched.

The launchsettings.json file is only used during development (not deployed).

As we just saw, Visual Studio will automatically create a launchsettings.json file if one doesn’t already exist and will choose some random port numbers for the app.

{
  "profiles": {
    "AddressBook.API": {  (1)
      "commandName": "Project",  (2)
      "launchBrowser": true,  (3)
      "environmentVariables": {  (4)
        "ASPNETCORE_ENVIRONMENT": "Development"
      },
      "applicationUrl": "https://localhost:61583;http://localhost:61584"
    }
  }
}
1 The name of the launch profile. This will appear in the target dropdown in the Visual Studio toolbar.
2 Specifies if the project should be launched directly or if IIS should be used. Other options include IIS and IISExpress.
3 Whether Visual Studio should also automatically launch a web browser and send a request to the app.
4 Provides the ability to temporarily add or override system environment variables.

We will discuss the ASPNETCORE_ENVIRONMENT variable later in this section.

The launchsettings.json file can be modified directly, or you can use the project properties window in Visual Studio.

Modify launch settings

  1. Change the launchBrowser setting to false

  2. Modify the applicationUrl setting.

    • Remove the https URL.

    • Change the http URL to use port 5000

  3. Save the file.

Runtime Environment

Every ASP.NET Core app will have access to a string value that represents the current runtime environment. The runtime environment can be set to any string but there are three standard values defined by the framework: Production, Staging, and Development.

As we will see, many aspects of the app will be affected based on the current runtime environment (configuration, logging, error handling, etc.)

The runtime environment is determined by the value of the ASPNETCORE_ENVIRONMENT system environment variable. This provides a way to set the default environment for every ASP.NET Core app on the system.

The ASPNETCORE_ENVIRONMENT environment variable can be overriden via a launchsettings.json profile or by using the --environment option when running the app:

dotnet run --environment Staging

If not set anywhere, the runtime environment will default to Production.
