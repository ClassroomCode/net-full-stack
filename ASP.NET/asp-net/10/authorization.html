Authorization

Authorization refers to the process that determines what a user is permitted to do. In an ASP.NET Core app, the primary job of the authentication middleware is to use information in the incoming request to set the User property of the HttpContext. All authorization decisions that happen later in the pipeline are made based on the value of the User property.

Authorize Attribute

If applied to an endpoint, the Authorize attribute will examine the User property to ensure the client has been successfully authenticated before the endpoint is executed.

[HttpDelete("customer/{id}")]
[Authorize]
public ActionResult DeleteCustomer(string id)

If the Authorize attribute is applied to the controller, it will have the same effect as applying the attribute to all of the controller’s actions.

[ApiController]
[Authorize]
public class CustomerController(NorthwindContext db) : ControllerBase
Enable authorization

  1. Add the authorization services.

    builder.Services.AddAuthorization();

  2. Add the authorization middleware immediately after the call to UseAuthentication

    app.UseAuthorization();

  3. Add the Authorize attribute to CustomerController

  4. Run the app and try to invoke an endpoint without including a token. The result should be 401 (Unauthorized).

  5. Invoke the login endpoint to obtain a JWT.

  6. Add the JWT as the value of the Authorization header and send the request. It should succeed.

    GET http://localhost:5000/customer
Authorization: Bearer <jwt_token>

  7. Stop the app and temporarily comment-out the Authorize attribute in CustomerController to make testing easier.

    // [Authorize]

Function Level Access Control

Just because a client has been successfully authenticated does not mean that they should be able to perform the operation being attempted. The Authorize attribute provides some additional options or you can also examine the User object directly within the implementation of an endpoint.

public ActionResult DeleteCustomer(string id) {
  var username = User.Identity?.Name;

  if (User.HasClaim(ClaimTypes.Role, "admin")) {
    //
  }

Policy Based Authorization

To help with managing authorization rules, your application can define one or more named policies that require a specific set of claims.

builder.Services.AddAuthorization(options => {
    options.AddPolicy("AdminsOnly", policy =>
        policy.RequireClaim(ClaimTypes.Role, "admin"));
});

Access to endpoints can then be restricted by specifying the policy as part of the Authorize attribute.

[Authorize(Policy = "AdminsOnly")]
public ActionResult DeleteCustomer(string id)
