Entity Framework Core

Entity Framework (EF) is an object-relational mapping framework for .NET that was originally released for .NET Framework in 2008. In 2016, a completely new ORM framework was introduced that was branded as Entity Framework Core.

With EF Core, data access is performed using a model. A model is made up of entity classes and a context object that represents a session with the database. The context object allows for the querying and saving of data.

EF Core identifies model types by examining the types used when defining DbSet properties of a DbContext.

public class NorthwindContext : DbContext
{
    public DbSet<Customer> Customers { get; set; }
    public DbSet<Product> Products { get; set; }
}

Conventions

There are specific default conventions that EF Core will use unless configured otherwise:

  • Table names match the DbSet property names

  • Column names match the entity property names

  • A property with a name of Id or [class]Id is assumed to be a primary key

  • If an entity type has a collection property of another entity type, EF Core will recognize this as a "navigation property" used to access related entities

    public class Blog
{
    public int BlogId { get; set; }
    public string Url { get; set; }
    public int Rating { get; set; }
    public List<Post> Posts { get; set; }  // navigation property
}

  • A child entity will typically include a property for the parent entity as well as the foreign key

    public class Post
{
    public int PostId { get; set; }
    public string Title { get; set; }
    public string Content { get; set; }

    public int BlogId { get; set; }  // foreign key
    public Blog Blog { get; set; }   // parent entity
}

We will work more with database relationships in a later section.

Configuration

When something doesn’t match the conventions expected by EF Core, two different approaches can be used for model configuration:

  • Attributes on the model types

    [Table("Product")]
public class Product
{
  [Column("UnitPrice")]
  public Decimal Price { get; set;}
}

  • DbContext’s OnModelCreating method

    protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Product>().ToTable("Product");
    modelBuilder.Entity<Product>().Property(p => p.Price)
        .HasColumnName("UnitPrice");
}

Most things can be configured using either approach. However, there are a few items that can only be configured via OnConfiguring (e.g., compound primary keys).
DbContext

  1. Add a new folder to the AddressBook.API project named DataAccess.

  2. Add a new class to the DataAccess folder named NorthwindContext.

  3. Define the NorthwindContext as a subclass of DbContext and add a DbSet property for the Customer type. You will need to add a couple of using directives.

    public class NorthwindContext : DbContext
{
  public DbSet<Customer> Customers { get; set; }
}

  4. Add an override for the OnConfiguring method and call the UseSqlServer method with a database connection string. The details for the connection might need to be different depending on the instance of SQL Server that you are using.

    protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder) {
  optionsBuilder.UseSqlServer(@"Server=localhost;Database=Northwind;Integrated Security=True;TrustServerCertificate=True");
}

    The database connection string should typically not be included in the source code like this. Instead, it should be read from an external source by using the .NET configuration system. This code will be refactored in a later section.

  5. Build the solution to check for any compiler errors.

Querying

Language-Integrated Query (LINQ) can be used to query data via a DbContext. The underlying EF provider is responsible for transforming the LINQ expression into a command (e.g., SQL) that can be sent to the underlying database.

using var db = new NorthwindContext();

var allCustomers = db.Customers.ToList();

var usaCustomers = db.Customers
  .Where(c => c.Country == "USA")
  .ToList();
Database-driven endpoint

  1. In Program.cs, modify the existing terminal middleware to retrieve the first customer and return the CustomerID as the response.

    app.Run(async context => {
  using var db = new NorthwindContext();
  var customer = db.Customers.First();

  await context.Response.WriteAsync(customer.CustomerID);
});

  2. Run the application and make a request to http://localhost:5000 using a web browser. You should see ALFKI as the response.

  3. Stop the application.

Error handling and asynchronous data access will both be covered in later sections.

Logging

During development, it can be useful to see the SQL that EF Core is generating and sending to the database. The easiest way to do this is by calling the LogTo method in OnConfiguring.

Viewing the SQL

  1. Within the OnConfiguring method of NorthwindContext, add a call to LogTo

    optionsBuilder.LogTo(Console.WriteLine);

  2. Run the application, make another request, and check the console window for the executed SQL.

    SELECT TOP(1) [c].[CustomerID], [c].[Address], [c].[City], [c].[CompanyName],
[c].[ContactName], [c].[ContactTitle], [c].[Country], [c].[Fax], [c].[Phone],
[c].[PostalCode], [c].[Region] FROM [Customers] AS [c]
