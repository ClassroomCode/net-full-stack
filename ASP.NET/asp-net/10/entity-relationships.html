Entity Relationships

Database relationships define how data in different tables connect, primarily through primary and foreign keys. Relationships enable efficient data management, integrity, and retrieval. The three main types of relationships are:

  • One-to-One (1:1)

  • One-to-Many (1:N)

  • Many-to-Many (M:N) (requiring a junction table)

In EF Core, relationships can be identified using three different approaches:

  • By Convention: EF Core can automatically identify relationships based on default naming conventions.

  • Data Annotations: Attributes can be used to explicitly identify the fields that should be used to define a relationship (e.g., [ForeignKey])

  • Fluent API: Code within the OnModelCreating of a DbContext can be used to fully define the relationships that are present in the database.

Conventions

If an entity type has a collection property of another entity type, EF Core will recognize this as a "navigation property" used to access related entities.

public class Blog
{
    public int BlogId { get; set; }
    public string Url { get; set; }
    public int Rating { get; set; }
    public ICollection<Post> Posts { get; set; }  // navigation property
}

A child entity will typically include a properties for the parent entity type as well as for the foreign key value.

public class Post
{
    public int PostId { get; set; }
    public string Title { get; set; }
    public string Content { get; set; }

    public int BlogId { get; set; }  // foreign key
    public Blog Blog { get; set; }   // parent entity
}

In the case of a many-to-many relationship, you can define an entity that maps to the linking table or EF Core can manage the data in the linking table transparently.

Order entity

In the Northwind sample database, there is a table named Orders and each order is associated with a customer.

  1. Add a new class to the Entities folder named Order with a few properties.

    public class Order
{
  public int OrderID { get; set; }
  public DateTime? OrderDate { get; set; }
  public DateTime? ShippedDate { get; set; }
}

    The Orders table has many more properties but this will be enough for now.

  2. Add properties to the Order entity for the related customer.

    public string CustomerID { get; set; } = string.Empty;
public Customer? Customer { get; set; }

    Even though every order must have a related customer, the property of type Customer in the Order entity is marked as nullable because we might not want to always retrieve the related customer entity when we retrieve an order.

  3. Add a new DbSet property to NorthwindContext for the Order entity.

    public DbSet<Order> Orders { get; set; }

  4. Add a navigation property to the Customer entity for the related orders.

    public ICollection<Order> Orders { get; set; } = new List<Order>();

  5. Build the solution and check for any compiler errors.

Querying Related Entities

EF Core will not automatically load related entities. There are three different approaches that can be used to control when related entities are loaded:

  • Eager Loading: The Include method can be used to specify that related data should be included in the results. This will usually result in a single JOIN query being used.

    var blogs = context.Blogs
    .Include(blog => blog.Posts)
    .ToList();

  • Explicit Loading: If an entity has already been loaded, you can use the Load method to explicitly load related entities.

    context.Entry(blog)
    .Collection(b => b.Posts)
    .Load();

  • Lazy Loading: When enabled, related data will be transparently loaded when a navigation property is accessed. The simplest way to use lazy loading is by installing the Microsoft.EntityFrameworkCore.Proxies package.

    Extra care must be taken when using lazy loading to avoid unneeded extra database roundtrips to occur. Refer to the documentation for more information.
Eager loading

The goal of this exercise will be to load related order data when retrieving an individual customer (but not when retrieving all customers).

  1. Modify the GetCustomer action in CustomerController to load the related orders.

    var customer = db.Customers
  .Include(c => c.Orders)
  .SingleOrDefault(c => c.CustomerID == id);

    In addition to the Include method, SingleOrDefault has to be used instead of Find because of some context caching capabilities that are built into Find

  2. Run the app and invoke the endpoint (the customer with an ID of "GREAL" has some orders). You should receive a 500 (Internal Server Error).

    The reason for the error is that the system is attempting to serialize all of the properties of the customer (including the navigation properties) and this results in a serialization cycle (customer → order → customer → …​)

Serialization Cycles

There are a few different approaches for how to handle a cycle when attempting to serialize a graph of entities into JSON.

  • Data Transfer Objects (DTOs): Instead of serializing the entities themselves, use the entity data to construct a type that is built to match you want to be sent to the client. Since the DTO will not have any navigation properties, it can be serialized without encountering a cycle.

  • JsonIgnore Attribute: The JsonIgnore attribute can be applied to a navigation property to prevent it from being serialized.

    [JsonIgnore]
public Customer? Customer { get; set; }

  • Configure JSON Serializer: The JSON serializer can be configured to ignore cycles globally. This will result in the navigation properties being skipped when a cycle would be created. This is the approach that we will use.

Prevent cycles

  1. Modify the call to AddControllers in Program.cs to configure the JSON serializer to ignore cycles.

    builder.Services.AddControllers().AddJsonOptions(options => {
  options.JsonSerializerOptions.ReferenceHandler =
    System.Text.Json.Serialization.ReferenceHandler.IgnoreCycles;
});

  2. Run the app and try to execute the endpoint again.

    Notice that each order includes a property for customer and customerID. One of the other approaches discussed above could be used to obtain better control over what appears in the JSON.
