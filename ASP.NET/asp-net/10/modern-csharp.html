Modern C#

Programming Paradigms

Imperative

Imperative programming involves a sequence of explicit step-by-step commands that tell the computer how to achieve a result by manipulating program state.

var nums = new List<int> { 1, 2, 3, 4, 5 };
var evens = new List<int>();
foreach (var num in nums) {
  if (num % 2 == 0) {
    evens.Add(num);
  }
}

Procedural

In procedural programming, code is organized into reusable blocks called procedures, functions, or subroutines to perform specific tasks.

var nums = new List<int> { 1, 2, 3, 4, 5 };
var evens = new List<int>();
foreach (var num in nums) {
  if (IsEven(num)) {
    evens.Add(num);
  }
}

Object-Oriented

With object-oriented programming (OOP), code is organized around objects. The objects bundle data (properties) and the functions (methods) that operate on that data. Key principles include abstraction, encapsulation, inheritance, and polymorphism.

Declarative

Declarative programming focuses on what you want to achieve, not how, by describing the desired result, while the system figures out the steps. This style hides often complex implementation details and control flow.

var nums = new List<int> { 1, 2, 3, 4, 5 };
var evens = nums.FindAll(IsEven);

Functional

Functional programming focuses on building applications by composing pure functions and treating functions as first-class citizens. Shared state and mutable data are avoided which leads to more declarative, predictable, and testable code.

Key concepts of functional programming include immutability, pure functions, higher-order functions, and recursion.

var nums = new List<int> { 1, 2, 3, 4, 5 };
var evens = nums.Where(n => n % 2 == 0);

Nullability

The value null is used to indicate the absence of a value for a variable or reference. In .NET, accessing a null reference at runtime results in a NullReferenceException.

Person person = null;
Console.WriteLine(person.FirstName);

Value types in .NET (int, struct, etc.) cannot be null. To enable nullability, a generic wrapper type of Nullable<T> must be used.

Nullable<int> a = 5;  // or... int? a = 5;
a = null;

Care must be taken when accessing the value of a nullable value type.

if (a is int val) {
  Console.WriteLine(val);
}
int val = a ?? 0;

Reference types in .NET can always be null.

Person p = null;

If nullable reference types are enabled for a project, setting a reference type to null or dereferencing a possibly null reference will generate a compiler warning.

<Nullable>enable</Nullable>

The ? operator can be used to tell the compiler that a reference type should be allowed to be null.

Person p = null;

Like with nullable value types, similar techniques should be used when working with a nullable reference type.

if (p is not null) {
  Console.WriteLine(val.FirstName);
}
Console.WriteLine(p?.FirstName ?? "unknown");
Person val = p ?? new Person();

Immutability

  • Thread Safety: Immutable objects are naturally thread-safe, removing the need for complex synchronization and simplifying concurrent programming.

  • Predictability: Data consistency is maintained throughout an object’s life, preventing unexpected side effects and making code easier to understand, test, and maintain.

  • Optimization: Immutable objects can be safely cached and used efficiently in data structures.

By default, all function parameters are passed by value. This means that a function receives a copy of the value if it’s a value type or a copy of the reference if it’s a reference type.

This behavior represents effective immutability for value type arguments since the function cannot modify the value in the caller (which would be considered a side effect).

For a reference type argument passed by value, the function cannot modify what the caller’s reference points to but it can potentially modify the state of the underlying object. For effective immutability of a reference type argument, the caller would need to either…

  • Make a deep copy of the object and pass that to the function.

  • Ensure the properties of the object itself are immutable.

There are manual ways to define an immutable reference type.

  • Use a required constructor to initialize state that is only accessible via read-only properties.

  • Use required init-only properties.

public class Person {
  public required string FirstName { get; init; }
}

Record Types

A newer way to create an immutable reference type in C# is to define a record type.

public record Person(string FirstName, string LastName);

The with expression can be used to achieve nondestructive mutation by creating a new instance.

Person p1 = new Person("Bill", "Gates");
Person p2 = p1 with { LastName = "Jobs" };

Record types also support value semantics for equality.

Person p1 = new Person("Bill", "Gates");
Person p2 = new Person("Bill", "Gates");

// p1 == p2 evaluates to true even though
// p1 and p2 refer to different objects in memory

Deferred Execution

In declarative code, it is important to identify when specific work will be performed.

  • Determines where error handling should be implemented.

  • Helps to avoid unnecessary work from being performed.

foreach (var p in products) {  // SQL executed here
  //
}

foreach (var p in products) {  // SQL executed again
  //
