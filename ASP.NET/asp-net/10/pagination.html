Pagination

API pagination is a technique for managing and retrieving large datasets by breaking them into smaller, manageable subsets. This improves performance, reduces server load, and enhances the user experience by providing faster response times and preventing data overload.

  • Offset-Based Pagination: Client provides a value for limit (starting point) and offset (number of items to return). This approach tends to be the simplest to implement but can be inefficient for large data sets and can be susceptible to "page drift" if data is added or removed.

    GET /customers?offset=20&limit=10

  • Page-Based Pagination: Uses page and size where the server calculates the offset internally. Has similar performance limitations as offset-based pagination.

    GET /customers?page=2&per_page=10

  • Keyset-Based Pagination: Uses a value that exists within the dataset to identify the starting point for the next set of items. The client passes a value from the previous response in its next request. This is more efficient for large, real-time, or frequently changing datasets because it avoids scanning large numbers of records and handles data changes better. However, this approach does not support random-access (where a client can jump to any specific page).

    GET /customers?start_key=greal&limit=10

EF Core Support

In EF Core, the Skip and Take methods get translated into OFFSET and FETCH NEXT (or LIMIT and OFFSET) clauses in SQL queries. This makes them a good fit for implementing offset-based pagination.

var customers = db.Customers
  .OrderBy(c => c.CustomerID)
  .Skip(20).Take(10)
  .ToList();

It is important to sort on a unique field (or a combination of fields) to ensure consistent page breaks.

For keyset-based pagination, a WHERE clause is used to limit the number of rows that must be processed by the database server.

var customers = db.Customers
  .OrderBy(c => c.CustomerID)
  .Where(c => c.CustomerID > "GREAL")
  .Take(10)
  .ToList();
Pagination for customers

For this exercise, we will implement offset-based pagination for the endpoint used to retrieve customers. The client will be responsible for deciding on the offset and limit to request but the should not allow a limit greater than 20.

  1. Modify the GetAllCustomers endpoint to receive two optional parameters (offset and limit) with some reasonable default values.

    public ActionResult<Customer[]> GetAllCustomers(int offset = 0, int limit = 10)

  2. Perform some basic input validation.

    if (offset < 0) {
  return BadRequest(new { message = "Offset must be positive" });
}
if (limit < 1 || limit > 20) {
  return BadRequest(new { message = "Limit must be in the range 1-20" });
}

  3. Modify the query to use Skip and Take

    var customers = db.Customers
  .OrderBy(c => c.CustomerID)
  .Skip(offset).Take(limit)
  .ToList();

  4. Run the app and test the endpoint.

    GET http://localhost:5000/customer?offset=20&limit=10
