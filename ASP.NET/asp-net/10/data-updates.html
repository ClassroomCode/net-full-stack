Data Updates

The AddressBook API project currently has two retrieval (GET) endpoints. In this section, we will discuss entity creation (POST), updates (PUT / PATCH), and deletion (DELETE).

EF Core Change Tracking

By default, a DbContext will track changes made to entities that have been retrieved via the DbContext. Changes will be applied to the underlying data source when SaveChanges is called.

var customer = db.Customers.Find(id);
customer.ContactName = "New Value";
db.SaveChanges();

The SaveChanges method will wrap all changes within a single database transaction and return the number of rows affected. The method will also update any database-generated properties (e.g., auto-incrementing primary key).

With an API, it is common to perform a query for entities that will not be modified during the current request. In that case, a "no-tracking" query can be used.

var customers = db.Customers
  .AsNoTracking()
  .ToList();

This type of query is more efficient since there is no need for EF to manage change tracking information.

Create (POST)

For endpoints used to create a new resource, the HTTP POST method should be used and the body of the request should include a JSON representation of the new resource to create.

If a controller action accepts a parameter of a complex type, the ASP.NET Core model binding system will create an object of that type and attempt to populate all of its properties from data in the incoming request.

public ActionResult CreateCustomer(Customer customer) { ... }

There are several ways to implement custom input validation when receiving incoming data. This will be addressed in another section.

If successful, the response should include:

  • HTTP 201 (Created) status code

  • HTTP Location header set to the URL of the newly created resource

    This is especially useful when the ID of the newly created resource is generated on the server side (e.g., auto-incrementing primary key).

  • Body containing a representation of the newly created resource

    Useful when code on the server might make changes to the data before it is saved (e.g., reformating of a phone number or street address). Including the modified resource in the response allows the client to display up-to-date information without the need to send an additional request.

The CreatedAtAction helper method can be used to generate a response that includes all of these items.

return CreateAtAction("GetCustomer", new { id = customer.Id }, customer);

The first two parameters (controller action name and route value parameter collection) are used to generate the URL for the Location header while the final parameter is the object that will be sent as the body of the response.

Endpoint to create a customer

  1. Add a new action to CustomerController for creating a new customer.

    [HttpPost("customer")]
public ActionResult CreateCustomer(Customer customer) {
  db.Customers.Add(customer);
  db.SaveChanges();

  return CreatedAtAction("GetCustomer",
    new { id = customer.CustomerID }, customer);
}

  2. Add a request to the tests.http file. Only CustomerID and CompanyName are required but feel free to provide more fields if you would like.

    POST http://localhost:5000/customer
Content-Type: application/json
{
  "customerID": "BLGTS",
  "companyName": "Microsoft",
  "contactName": "Bill Gates"
}

  3. Run the app and test the new endpoint. Use one of the GET endpoints to confirm that the entity was added.

  4. Stop the app.

Update / Create (PUT)

When modifying an existing resource, the HTTP PUT and PATCH methods are both applicable. The definition of the PUT method states that it "replaces a representation of the target resource with the request content". The PUT method may also add a new resource if attempting to replace a resource that does not currently exist. In either case, the client is expected to provide the entire resource (i.e., all required fields) in the body of the request.

If successful and the action resulted in the creation of a new resource, the response should be the same as that for a successful POST. If, on the other hand, an existing resource was successfully modified, the response should use the HTTP 204 (No Content) status code.

To update a tracked entity with data from an incoming request, the fields can be updated individually or the CurrentValues.SetValues method can be used. In either case, EF Core will generate SQL to update only the fields that have a value that differs from the field’s original value.

Endpoint to update a customer

  1. Add a new action to CustomerController for responding to a PUT request.

    [HttpPut("customer/{id}")]
public ActionResult PutCustomer(string id, Customer customer) {
  var existingCustomer = db.Customers.Find(id);
  if (existingCustomer is null) {
    db.Customers.Add(customer);
    db.SaveChanges();
    return CreatedAtAction("GetCustomer",
      new { id = customer.CustomerID }, customer);
  }
  else {
    db.Entry(existingCustomer).CurrentValues.SetValues(customer);
    db.SaveChanges();
    return NoContent();
  }
}

  2. Test the new endpoint.

    PUT http://localhost:5000/customer/blgts
Content-Type: application/json
{
  "customerID": "BLGTS",
  "companyName": "Microsoft",
  "contactName": "William Gates"
}

    Remember that a PUT operation expects all of the fields to be present in the request. If a field is missing, that field will be set to null (if the field in the database allows nulls).

Update (PATCH)

The PATCH method is used to apply partial modifications to an existing resource. The request body should only contain the fields that are intended to be modified.

Like PUT, if the action successfully modifies an existing resource, the response should be an HTTP 204 (No Content). However, different from PUT, if the resource does not currently exist, the response should be 404 (Not Found).

Since implementing a generic PATCH endpoint for an endpoint can be more complex, many Web APIs do not provide one but Microsoft does provide a Microsoft.AspNetCore.JsonPatch NuGet package to help with implementing a PATCH endpoint.

Delete

The HTTP DELETE method is used to ask a server to delete a specified resource.

If successfully able to delete the resource, the response should be an HTTP 204 (No Content). If a request is made to delete a resource that does not currently exist, the response should be an HTTP 404 (Not Found).

Endpoint to delete a customer

  1. Add a new action to CustomerController for responding to a DELETE request.

    [HttpDelete("customer/{id}")]
public ActionResult DeleteCustomer(string id) {
  var existingCustomer = db.Customers.Find(id);
  if (existingCustomer is null) {
    return NotFound();
  }
  else {
    db.Customers.Remove(existingCustomer);
    db.SaveChanges();
    return NoContent();
  }
}

  2. Test the new endpoint.

    DELETE http://localhost:5000/customer/blgts

Many apps have the requirement to implement "soft delete". In that case, the DELETE endpoint might modify a field (e.g., IsActive) instead of performing an actual delete.
