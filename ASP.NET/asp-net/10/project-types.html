Project Types

The .NET SDK offers a variety of project types and associated templates. It is important to choose the right project type based on the role the component will play in your technology stack.

Minimal APIs

Minimal APIs are architected to create HTTP APIs with minimal dependencies. They’re ideal for microservices and apps that want to include only the minimum files, features, and dependencies.

app.MapGet("/", () => "Hello World!");
app.MapGet("/customer", () => {
  using var db = new NorthwindContext();
  var customers = db.Customers.ToList();
  return customers;
});

Minimal APIs can result in less boilerplate code and can often easily be adapted to work in a serverless environment. However, minimal APIs lack many of the built-in features provided by controller-based APIs and can be difficult to maintain for larger, more complex applications.

Model-View-Controller (MVC)

Rather than defining endpoints with function-based handlers (in the style used by minimal APIs), it is also possible to take a Model-View-Controller (MVC) approach and use separate controllers to handle incoming requests.

This approach can be used to build both Web APIs and Web UIs (server-generated HTML).

[ApiController]
public class CustomerController : ControllerBase
{
  [HttpGet("customer")]
  public ActionResult GetAllCustomers() {
    using var db = new NorthwindContext();
    var customers = db.Customers.ToList();
    return Ok(customers);
  }
}
public class CustomerController : Controller
{
  [HttpGet("customer")]
  public ActionResult GetAllCustomers() {
    using var db = new NorthwindContext();
    var customers = db.Customers.ToList();
    return View(customers);
  }
}

Razor Pages

Razor Pages is a page-focused model for building a server rendered web UI. Content is dynamically rendered on the server in response to a browser request and that content is returned to the client in a form that is ready for display. Rendered content may consist of HTML, CSS, and JavaScript.

@page
@model IndexModel

<h2>Hello Razor Pages</h2>
<p>The current server time is: <strong>@Model.Message</strong></p>

When compared to MVC, a Razor Page typically fulfills the job of both the controller and the view while the model (or view model) is still defined separately.

Blazor

Blazor is a component-based framework that supports both server-side rendering and client interactivity.

  • Static server-side rendering: Content is delivered to the browser in a way that is similar to Razor Pages and MVC.

  • Interactive server-side rendering: UI interactions are handled on the server over a real-time connection with the browser.

  • Client-side rendering: Allows .NET code to run in the browser by using a version of the .NET runtime built with WebAssembly.

Since Blazor supports these different render modes (and since they can be used together in a single project), Blazor is now recommended by Microsoft for most Web UI projects.

Class Libraries

In .NET, a class library is an assembly that contains functionality that can be used by other .NET assemblies. Separating code into a class library can result in code that is easier to maintain, reuse, and test.

A class library can be download by a browser and its code executed by the WebAssembly version of the .NET runtime.

Unit Testing

Unit tests are defined in one or more separate class library assemblies and reference the assemblies containing the code to be tested.

Tests within a unit test library are discovered and executed by a test runner (often the .NET CLI or an IDE like Visual Studio).
