Logging

Like the configuration system, the logging system in ASP.NET Core is built around the concept of providers. By default, the CreateBuilder method adds the following logging providers:

  • Console: Logs output to the console

  • Debug: Writes output using the System.Diagnostics.Debug class

  • EventSource: Writes to a cross-platform event source with the name Microsoft-Extensions-Logging (can be consumed by other tools)

  • EventLog: If running on Windows, writes to the Windows Event Log

The collection of logging providers can be modified during app startup:

builder.Logging.ClearProviders();
builder.Logging.AddConsole();

Create Logs

Regardless of the providers that are configured, the method used create logs remains the same. An instance if ILogger should be obtained via dependency injection:

public class TodoController(ILogger<TodoController> logger) : ControllerBase

The ILogger type defines a Log method for formatting and writing a log message. The first parameter of the Log method is of type LogLevel:

  • Trace

  • Debug

  • Information

  • Warning

  • Error

  • Critical

There are also extension methods on ILogger for each of these log levels (e.g., LogWarning). An appropriate log level should be used based on the type of information being logged.

logger.LogInformation("New to-do item created with id of {id}", id);

Configuration

The configuration system can be used to specify the minimum log level recorded. This may of course be different for different environments.

{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}

For the example above, a log message generated by an ASP.NET Core framework component will only be recorded if it has a log level of Warning, Error, or Critical.

Refer to the documentation for more logging configuration examples.

Logging Exceptions

All the ILogger methods include an overload that accepts an exception parameter. This should be used when writing a log message due to an exception. How this information is presented is provider-specific.

catch (Exception ex) {
    logger.LogError(ex, "Unable to retrieve to-do items");
}

Third-Party Logging Providers

There are a large number of third-party logging providers that include specific support for ASP.NET Core. Here is a partial list:

  • elmah.io

  • Gelf

  • JSNLog

  • KissLog.net

  • Log4Net

  • NLog

  • PLogger

  • Sentry

  • Serilog

  • Stackdriver

The way a specific provider is configured may be unique. However, the way that log messages are written (ILogger) does not change.

The most popular logging framework among ASP.NET Core developers for the past several years has been Serilog (1.5 billion total downloads of the main NuGet package).
