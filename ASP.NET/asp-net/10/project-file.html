Project File

Every .NET project must include a project file. The project file is an XML file with an extension that reflects the language used for the project (.csproj for C#).

When building a project, the Microsoft Build Engine (MSBuild) processes the project file to determine things like:

  • Version of the .NET Runtime being targeted

  • Optional settings that affect the build process

  • Static content files to include in the build output

  • Other required assemblies (project and package references)

  • Additional tasks to perform as part of the build process

The SDK provides a collection of project starter templates and these can be used within Visual Studio via the New Project dialog. However, for this first project, to better understand and how everything works, we will create the initial project and solution files manually by using the command line and a simple text editor.

Project directory

  1. Create a directory named AddressBook that will serve as the parent directory for several related projects.

  2. Create a new subdirectory under AddressBook named AddressBook.API. This directory will be the home an ASP.NET Core API project.

  3. Use your preferred text editor to create a new text file that will be the project file.

The Project Element

The Project element is the root element of every project file. An attribute of this element is used to specify the SDK that will be used when building the project. For an ASP.NET Core project, we want to use Microsoft.NET.Sdk.Web as the value for the Sdk attribute.

Add the Project element

  1. Add the Project element and Sdk attribute to the project file.

    <Project Sdk="Microsoft.NET.Sdk.Web">
</Project>

  2. Save the file in the AddressBook.API directory with a name of AddressBook.API.csproj

    Make sure your text editor doesn’t add a .txt extension on to the file. If it does, rename the file so the extension is .csproj

Using Microsoft.NET.Sdk.Web will configure the project with web-specific settings and dependencies. Specifically, the project will reference the .NET assemblies in the runtime package store that are included by default for an ASP.NET Core app.

If you would like to see the list of assemblies that are implicitly referenced, you can look under the "Dependencies" item in Visual Studio’s Solution Explorer or you can look at the Microsoft.AspNetCore.App.deps.json file in the shared folder of the system’s dotnet directory.

Target Framework Moniker (TFM)

Another item required to be in the project file is the .NET Target Framework Moniker (TFM). This determines the set of APIs that are available to use within the project and which version of the runtime is required to run the app.

<TargetFramework>net10.0</TargetFramework>

When upgrading a project to a newer version of .NET, updating the TFM is often the only change that must be made. After that, existing code can optionally be modified to take advantage of new features.

Opt-In Features

Sometimes, Microsoft will introduce a new feature that you must explicitly enable to use. This is typically done when automatically enabling the feature for an existing project could result in compiler errors that need to be addressed.

There are two such features that we will enable for our new project:

  • Implicit usings: Adds common global using directives

  • Nullable reference types: Improved static flow analysis to determine when a variable might be null before dereferencing it

Since these features are enabled in the SDK project templates, we will enable them now. However, we will wait until later to discuss the details.
Add the TFM and enable features

  1. Inside of the Project element in the project file, add a property group with a TFM for .NET 10.0 and enable both nullable reference types as well as implicit usings.

    <PropertyGroup>
  <TargetFramework>net10.0</TargetFramework>
  <Nullable>enable</Nullable>
  <ImplicitUsings>enable</ImplicitUsings>
</PropertyGroup>

  2. Save the project file.
