Input Validation

Whenever any data from the client is being used to perform an action, it is important to have validation in place. This applies to not only URL parameters and body content but also HTTP header values.

Validation Attributes

When a controller action is invoked, the model binding system that attempts to populate the parameters of the action. During this process, if the model binding system encounters a basic binding problem (type mismatch), it will immediately return a 400 (Bad Request).

You can use attributes from the System.ComponentModel.DataAnnotations namespace to specify additional validation rules for entity properties. The model binding system will check these attributes during the binding process.

Validation attribute

In the Northwind database, every customers should have an ID that is exactly 5 characters in length.

  1. In Customer.cs, add a Length attribute to the CustomerID property.

    [Length(5, 5)]
public string CustomerID { get; set; } = string.Empty;

  2. Run the app and try to add a new customer with a value for CustomerID that is not of the correct length. Notice that the response status code is 400 (Bad Request) and the body contains a JSON payload with an errors collection and the message…​

    "The field CustomerID must be a string or collection type
  with a minimum length of '5' and maximum length of '5'."

  3. Modify the Length attribute to include a custom error message.

    [Length(5, 5, ErrorMessage = "ID must be 5 characters")]

  4. Test the endpoint again and confirm that the custom error message appears in the response.

There is a large collection of built-in validation attributes (including one that performs validation using a regular expression). Refer to the documentation for a complete list.

Model State

Validation attributes can work well for simple validation (required, range, length, etc.) For more complex validation, you can execute code within the action and add errors to the ModelState property.

ModelState.AddModelError("Country", "Invalid country");

The ValidationProblem helper method can be used to generate a response in the same JSON format that is generated by the model binding system.

return ValidationProblem();
Custom validation

  1. In CustomerController, add code to the beginning of the CreateCustomer action that checks if the CustomerID is already in use and return an appropriate response.

    var existingCustomer = db.Customers.Find(customer.CustomerID);
if (existingCustomer is not null) {
  ModelState.AddModelError("CustomerID", "A customer with this ID already exists");
}
if (!ModelState.IsValid) return ValidationProblem();

    We are checking the IsValid property of ModelState separately (instead of returning inside of the validation logic) so that it will be easier to add more validation rules later.

  2. Test the new validation logic.
