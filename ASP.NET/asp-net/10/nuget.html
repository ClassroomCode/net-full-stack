NuGet

NuGet is the package manager for .NET. It enables developers to create, share, and consume useful .NET libraries. NuGet client tools provide the ability to produce and consume these libraries as "packages". NuGet provides functionality similar to that provided by npm for JavaScript.

Packages

A NuGet package is a ZIP file with the .nupkg extension that contains compiled code (DLLs), other files related to that code, and a manifest file that includes information like the package’s version number.

Some NuGet packages do not directly include any assemblies but only reference other NuGet packages. This type of package is called a "metapackage", and it helps to simplify dependency management by allowing you to manage a collection of packages as a single unit.

NuGet.org

NuGet.org is the primary public host of NuGet packages and is the default package source used by the CLI and Visual Studio.

Microsoft uses NuGet.org to distribute officially supported packages. However, anyone can create an account and publish a package to NuGet.org. Therefore, you should exercise caution when adding a package to your project. Some questions that you may want to ask include:

  • Who is the publisher of the package?

  • Is it well maintained and supported?

  • Is it approved for use within my organization?

There are other NuGet hosts that offer additional services as well as the ability to manage your own private package repository (myget.org is one example).

There are also options for setting up a custom internal private NuGet feed. Refer to the documentation for more information.

Consuming Packages

You reference a NuGet package by adding a PackageReference element to the project file.

<PackageReference Include="Microsoft.EntityFrameworkCore" Version="10.0.1" />

Rather than editing the project file by hand, you can use the .NET CLI or a visual interface provided by your IDE.

dotnet add package Microsoft.EntityFrameworkCore -v 10.0.1

If you do not specify a version number when using the CLI command, a reference will be added for the newest version available (that is not identified as "pre-release"). If you want to use a pre-release version, you can include the --prerelease option.

It is possible to use a wildcard in the version number (9.*) but this is generally not recommended. Instead, it is better to maintain more control over when a newer version of a dependency starts to be used by a project.

IDEs like Visual Studio will provide a visual indication when a newer version of a package is available.

The restore command is used to scan the list of package references and download any that are not already in the system’s local package cache.

dotnet restore

The restore command can be executed explicitly at any time. However, the following commands will also implicitly call restore:

  • dotnet add package: Adds the reference to the project file and also immediately calls restore.

  • dotnet build: Will automatically call restore if necessary.

  • dotnet run: Will automatically call build if necessary.

Add a NuGet package

  1. When in the same directory as the project file, use the CLI to add a package reference for the Entity Framework Core database provider for Microsoft SQL Server.

    dotnet add package Microsoft.EntityFrameworkCore.SqlServer

  2. Check the project file and confirm that a package reference was added.
